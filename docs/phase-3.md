# Phase 3 — gRPC / RPC Communication Between Distributed Department Nodes

## 1. Objective
Phase 3 introduces **inter-node Remote Procedure Call (RPC)** communication to the Decentralized Campus Resource Booking System using **gRPC** and **Protocol Buffers**.

While Phase 2 established database isolation and local REST endpoints, node communication was routed through the Gateway via HTTP. Phase 3 enables direct binary RPC calls between department nodes (`CSE`, `IT`, `E&TC`) over gRPC, allowing one node to query another node's resource inventory without directly accessing its database.

Key Phase 3 features:
1. Protocol Buffer schema definition (`backend/grpc_communication/proto/campus_resource.proto`).
2. Generated gRPC Python stubs and messages (`campus_resource_pb2.py` and `campus_resource_pb2_grpc.py`).
3. Reusable gRPC server implementation (`DepartmentNodeServicer` in `server.py`).
4. Reusable gRPC client wrapper (`get_remote_resources`, `get_remote_node_info` in `node_client.py`).
5. Port separation: HTTP ports (`50151`, `50152`, `50153`) and gRPC ports (`50051`, `50052`, `50053`).
6. Inter-node gRPC demonstration endpoint (`GET /remote-resources/{target_dept}`).
7. Graceful gRPC connection error handling (**HTTP 503 Service Unavailable**).
8. Interactive React frontend demonstration section.

## 3. Protocol Buffer Contract (`campus_resource.proto`)

```protobuf
syntax = "proto3";

package campus_resource;

service DepartmentNodeService {
    rpc GetNodeInfo (NodeInfoRequest) returns (NodeInfoResponse);
    rpc GetResources (ResourceRequest) returns (ResourceResponse);
}

message NodeInfoRequest {
    string requesting_node = 1;
}

message NodeInfoResponse {
    string node_name = 1;
    string status = 2;
}

message ResourceRequest {
    string department = 1;
}

message ResourceProto {
    int32 id = 1;
    string name = 2;
    string resource_type = 3;
    string location = 4;
    string department = 5;
    int32 capacity = 6;
    bool is_available = 7;
}

message ResourceResponse {
    string department = 1;
    repeated ResourceProto resources = 2;
}
```

## 4. Key gRPC Concepts

### Remote Procedure Call (RPC)
RPC is a computer communication protocol that allows a program to execute a subroutine/function in another address space or process without the programmer explicitly coding the details for the remote interaction.

### gRPC
gRPC is a high-performance, open-source universal RPC framework developed by Google. It uses HTTP/2 for transport and Protocol Buffers as its interface definition language.

### Protocol Buffers (Protobuf)
Protocol Buffers are Google's language-neutral, platform-neutral, extensible mechanism for serializing structured data in binary format.

### Stub
A client-side proxy object generated by protoc compiler. The stub exposes the same RPC methods defined in `.proto` and handles serializing requests and deserializing responses.

### Channel
An abstraction of a long-lived HTTP/2 connection to a remote gRPC server endpoint (e.g. `127.0.0.1:50052`).

## 5. Demonstration Flow (CSE -> IT via gRPC)

1. User clicks **"CSE Node -> IT Node (gRPC Port 50052)"** in React frontend.
2. Frontend sends HTTP GET request to Gateway: `GET http://127.0.0.1:8000/api/departments/cse/remote-resources/it`.
3. Gateway forwards request to CSE Node HTTP endpoint: `GET http://127.0.0.1:50151/remote-resources/it`.
4. CSE Node calls `get_remote_resources("IT")` in `node_client.py`.
5. `node_client.py` opens a gRPC channel to IT node on `127.0.0.1:50052` and invokes `stub.GetResources()`.
6. IT Node's gRPC server (`DepartmentNodeServicer`) receives the RPC request.
7. IT Servicer queries its local `it.db` SQLite database using `get_all_resources("database/it.db")`.
8. IT Servicer packages the SQLite rows into `ResourceProto` objects and sends `ResourceResponse` back over gRPC.
9. CSE Node receives binary response, converts `ResourceProto` objects to JSON dictionaries, and returns them in the HTTP response to Gateway -> Frontend.

> [!IMPORTANT]
> **Strict Database Isolation**:
> The CSE Node **never** directly accesses `it.db` or `entc.db`. IT's data is retrieved exclusively by invoking IT Node's `GetResources` gRPC endpoint.

## 6. Failure Handling (Simulated Offline Node)

If the IT gRPC server is shut down or unreachable:
1. CSE Node's gRPC call catches `grpc.RpcError` (`StatusCode.UNAVAILABLE` or `StatusCode.DEADLINE_EXCEEDED`).
2. CSE Node returns **HTTP 503 Service Unavailable** with payload:
   ```json
   {
       "detail": "Unable to contact IT node via gRPC (UNAVAILABLE): Server offline"
   }
   ```
3. The CSE Node and Gateway remain online without crashing.
